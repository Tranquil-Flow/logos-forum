2026-10-06 — second review of the source: fixes and cleanup, re-verified.

Fixes:
- Thread rows: brackets in an alias are shown as parentheses, so an alias
  can no longer fake a post state or push the real key id into the body.
- Topic rows: built with one .arg() call, so "%1" in a topic title is no
  longer substituted (it corrupted the label and the unread count).
- Received events dated more than an hour ahead of the reader's clock are
  refused (one event could pin its topic to the top of every list);
  received topic titles are bounded to 128 bytes like local ones.
- A database error while merging is reported as an error, not as "already
  here"; snapshot restores count such posts separately.
- History paging that fails after the first page says so on the History
  line instead of showing an earlier state.
- Downloaded snapshot files no longer pile up: a new restore removes the
  earlier downloads, so only the newest is kept.
- tools/windows_smoke.sh: the restart check now requires the reopened window
  to show the test post (UI Automation), not only the file on disk.
Cleanup: shared helpers for key rotation and Delivery's two "sent" signals,
one JSON reader, one launch and one SQL helper in the Windows smoke, clearer
per-case messages when a post cannot be stored, comments brought up to date.

Follow-up (same day, from a security review of the pushed branch): the post
header showed "alias · id <key>" as one elided text, so a long alias could
imitate a key id and push the real one out of view, and the author, topic
and status texts did not force plain text. Now the key id is drawn as its
own text (never elided), middle dots in an alias are shown as hyphens, and
every text showing network data is plain text.
- integration-3-alias-display.log: UI suite 15 passed, 0 failed (new test:
  an alias cannot fake a key id or a state).
- evidence/m5-package/ui-tour-20261006-b/: the new header, by eye.

Follow-up 2 (security review of the pushed branch): the row parser in the
view used "." (no line terminators), and aliases/titles could carry line or
paragraph separators, bidi overrides, zero-width characters and look-alike
dots. Author-chosen text is now cleaned for display (displaySafe in the
backend: such characters become U+FFFD, look-alike dots become hyphens) and
the parser accepts any character.
- integration-4-display-safe.log: UI suite 15 passed, 0 failed (the spoof
  test now also uses U+2028, U+202E and U+22C5).
Follow-up 3 (Windows CI run 37464920456): restoring a snapshot served by
